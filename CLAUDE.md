# QuizZap

Offline LAN multiplayer quiz game for Android/iOS. One device hosts (TCP server + NSD broadcast); others join as clients on the same WiFi/hotspot. No internet required.

> **For future Claude sessions:** read this file first. It is the index. Don't crawl the whole tree — use the **Feature → file map** at the bottom to jump to the right file. Use `architectural_patterns.md` for deeper conventions only when relevant.

## Tech Stack

| Concern | Choice |
|---|---|
| Language | Dart 3, Flutter (Material 3) |
| State | Riverpod `StateNotifier` / `FutureProvider` |
| Navigation | GoRouter (declarative, single Navigator) |
| Database | sqflite (SQLite, hand-written DAOs) |
| Networking | `dart:io` `ServerSocket`/`Socket` + `nsd` |
| Charts / PDF | fl_chart, pdf |
| QR / Images | qr_flutter, image_picker |

**No code generation.** No build_runner, no Freezed, no json_serializable. All models, DAOs, and copyWith are hand-written. Nullable copyWith uses a `const Object _s = Object()` sentinel pattern.

## Essential Commands

```bash
flutter create .                  # Regenerates android/ios/ boilerplate (safe — never touches lib/)
flutter pub get
flutter run                       # On a connected device
flutter analyze                   # Static checks (zero errors expected)
flutter build apk --release
```

After `flutter create .`, restore the 6+ Android permissions from `android_manifest_permissions.txt` AND the image-picker permissions (CAMERA, READ_MEDIA_IMAGES, READ_EXTERNAL_STORAGE) in `android/app/src/main/AndroidManifest.xml`. Also restore the FLAG_SECURE MethodChannel handler in `MainActivity.kt`.

## Routes (`lib/router/app_router.dart`)

```
/                       Home
/library                Quiz library
/creator/:quizId        Creator (edit slides)
/preview/:quizId        Read-only preview of a quiz (extra: int initialIndex)
/host/settings          Game settings before hosting
/host/lobby             Lobby — waits for clients to join
/join                   Player join screen (auto-discover or manual IP)
/waiting                Player lobby
/question               Live question screen (host AND client share this widget)
/mid-leaderboard        Between-question leaderboard
/results                Final results
/report                 Host-only analytics + CSV/PDF export
/history                Past games
```

Game-state transitions are message-driven (see `message_models.dart`), not route-driven. The router only owns navigation between screens.

## Domain Vocabulary

- **Slide / Question** — used interchangeably; the model class is `Question`.
- **SlideType** (`lib/data/models/slide_type.dart`) — `buttons | checkboxes | reorder | range | typeAnswer | infoSlide`. Every branch on it MUST use an exhaustive `switch` expression — the analyzer will catch missing cases when a new type is added.
- **GameSession** — top-level Riverpod state held by `gameSessionProvider`. Distinguishes host vs client via `isHost`.
- **PIN** — 6-digit join code generated by `GameSessionNotifier.generatePin()`.

## Conventions Worth Remembering

1. **Singletons** (`AppDatabase`, `NetworkService`, `NsdHelper`) — private constructor + static `instance`. Riverpod providers wrap them but they live for the process lifetime.
2. **Immutable state + sentinel copyWith** — see `quiz_model.dart`, `game_settings.dart`, `game_session_provider.dart`.
3. **NDJSON over TCP port 4567** — every message is `jsonEncode(toJson()) + '\n'`. Framing logic lives in `NetworkService._attachLineReader`.
4. **Exit confirmations** — `lib/utils/confirm_exit.dart` is the single confirm dialog used everywhere. Game / lobby / creator all use it; on confirm they navigate to `/` (home), never back to the previous route.
5. **Back navigation policy** — anywhere the user presses back (system or AppBar IconButton), they end up at `/` (after any existing confirm). No screen pops to its previous route as a back action.
6. **Forfeit on backgrounding** — `question_screen.dart` listens to `AppLifecycleState.paused` ONLY (not `inactive`/`hidden`, which fire for transient interruptions like notification-shade pulls).
7. **Screenshot blocking** — Android only, via `ScreenSecurity.enable()` (FLAG_SECURE through MethodChannel `quizzapp/security`). iOS is a no-op.
8. **Image distribution** — Question images are stored locally as a file path. When the host broadcasts `QuestionMessage`, `QuestionMedia.toTransportableMap` upgrades the path to a `data:image/...;base64,…` URI (capped at 200 KB; oversized images are dropped from the message).
9. **Player count realistic ceiling** — the slider goes to 300 but the phone-host TCP architecture realistically supports ~80–150 players. With images, expect 30–50. 300 "without flaw" is aspirational and will require an HTTP image side-channel + ack-based question sync to actually achieve.

## Known Limitations & Tradeoffs

- **iOS screenshot blocking** is impossible (no public API). FLAG_SECURE is Android-only.
- **300 players** — see "Player count realistic ceiling" above.
- **Images over the wire** — currently base64-embedded in `QuestionMessage`. With the 200 KB cap, this works for small player counts but doesn't scale; future fix is an HTTP side-channel served by the host alongside the TCP server.
- **No reconnection logic** — a client that drops mid-game cannot rejoin the same session. Reconnects are a future feature.
- **Time sync is per-client-receipt** — each client's question timer starts when it receives the `QuestionMessage`. This is intentional (fair to slow clients) but means players see questions at slightly different real-time moments on a weak network.

## Adding things

- **New `SlideType`** — edit the enum, then fix the three exhaustive switches the analyzer will flag (creator editor, question screen, evaluator).
- **New `NetworkMessage` type** — add to `MessageType` enum, write the concrete class with `toJson`/`fromJson`, add a case in `NetworkMessage.parse`.
- **New nullable model field** — replicate the `_s` sentinel pattern in `copyWith`.
- **New screen** — add a `GoRoute` to `lib/router/app_router.dart`. Wrap with `PopScope` if back navigation should be intercepted; route to `/` on confirm to match the project-wide back policy.
